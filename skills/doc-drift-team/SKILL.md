# doc-drift-team

Agent Teams を活用し、複数のドキュメントチェッカーがドキュメントグループごとに並列でチェックを行うスキル。大量のドキュメントを効率的に検証する。

> **注意**: このスキルは Agent Teams を使用するため、通常の `doc-drift` スキルより多くのトークンを消費する。ドキュメントが少数の場合には `doc-drift` の使用を推奨する。

## 引数

`doc-drift` スキルと同じ:
- 引数なし: カレントディレクトリのプロジェクト全体をチェック
- パス指定: 特定のドキュメントやディレクトリに絞ってチェック

## 実行プロセス

### フェーズ1: ドキュメント探索とグループ分け

1. `doc-drift` スキルのフェーズ1と同じ手順でドキュメントを探索する
2. ドキュメントをグループに分ける（ディレクトリ単位またはテーマ単位で2〜4グループ）
   - 例: README 系、API 仕様書、セットアップガイド、アーキテクチャ文書

### フェーズ2: チーム編成と並列チェック

1. エージェントチームを作成する
2. **doc-checker** × N（グループ数に応じて2〜4名）をスポーンする
   - チェッカーは**読み取り専用**（コードもドキュメントも変更しない）
   - スポーンプロンプトに含める情報：
     - 担当ドキュメントグループの一覧
     - `doc-drift` スキルのチェック観点（API/インターフェース、データモデル、設定・環境変数、ディレクトリ構成、依存関係、使用例、機能説明、セットアップ手順、Git Hooks、エラーコード、権限、削除・廃止、未文書化）
     - 重大度の分類基準（🔴重大 / 🟠重要 / 🟡提案 / 🟢軽微）
     - レポート形式（ドキュメント側の箇所と実装側の箇所を両方記載）
3. 共有タスクリストにグループごとのチェックタスクを作成する

### フェーズ3: レポート統合

1. 全チェッカーの結果を収集する
2. `doc-drift` スキルのレポート形式に従い、統合レポートを生成する
3. 出力先を判定する：
   - `gh` コマンドが利用可能かつ git リポジトリ内 → GitHub Issue として作成する（タイトルは `review: ドキュメント乖離レポート(<ブランチ名>, <YYYY-MM-DD>)` の形式）
   - 上記が使えない場合 → プロジェクトルートに `doc-drift-report.md` を生成する
4. レポートの要約をユーザーに報告する

### フェーズ4: チーム解散

1. すべてのチームメイトにシャットダウンを要求する
2. チームリソースをクリーンアップする

## チームメイトの役割

| 役割 | 人数 | 責務 |
|------|------|------|
| doc-checker | 2〜4 | 担当ドキュメントグループの乖離チェック。読み取り専用 |

## ルール

- すべてのチェッカーは読み取り専用。コードもドキュメントも変更しない
- 各チェッカーは担当グループのドキュメントのみをチェックする
- 仕様書を正（Single Source of Truth）として扱う
- 乖離の報告にはドキュメント側と実装側の両方の箇所を示す
- 統合レポートは `doc-drift` スキルのレポート形式に従う
- 重大度の基準は `doc-drift` スキルと同一
- チームメイトがエラーで停止した場合、リードが確認し再スポーンまたは対処する
- 各フェーズの進捗は共有タスクリストで管理する
