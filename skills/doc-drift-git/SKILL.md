# doc-drift-git

git リモートブランチとの差分に含まれるドキュメント変更とコード変更を突き合わせ、乖離（ドリフト）を検出するスキル。
**両方とも差分から取得する。** プロジェクト全体のドキュメントを走査するのではなく、差分内の変更同士を突き合わせる。

PR 作成前にドキュメントの更新漏れがないか確認するのに最適。

## 引数

- 引数なし: 現在のブランチと `origin/develop` との差分を対象にする
- ブランチ指定: 比較先のリモートブランチを指定する（例: `origin/main`）

## 実行プロセス

### フェーズ1: 差分の取得と分類

1. リモートの最新情報を取得する（`git fetch origin`）
2. 比較元ブランチを決定する
   - 引数がある場合はそれを使用する
   - 引数なしの場合は `origin/develop` を使用する
3. マージベースを取得する（`git merge-base <比較元> HEAD`）
4. 差分のあるファイル一覧を取得する（`git diff --name-status <merge-base>...HEAD`）
5. コミット一覧を取得する（`git log --oneline <merge-base>..HEAD`）
6. 差分ファイルを分類する
   - **ドキュメントファイル**: `.md`, `.rst`, `.txt`（README、docs/、spec/、CLAUDE.md、ARCHITECTURE.md 等）
   - **コードファイル**: ソースコード、設定ファイル、マイグレーション、依存定義（package.json、go.mod 等）
   - **その他**: 画像、バイナリ等（チェック対象外）
7. ドキュメントファイルとコードファイルの両方が差分に含まれるかを確認する
8. TodoWrite でチェック対象をタスク化する

### フェーズ2: ドキュメント差分の分析

差分に含まれるドキュメントファイルの変更内容を分析する。

#### 手順

1. 各ドキュメントファイルの差分を取得する（`git diff <merge-base>...HEAD -- <ファイル>`）
2. 変更内容から、以下を抽出する
   - 追加された記述（新機能の説明、新しい手順、新しい設定項目など）
   - 変更された記述（既存の説明の修正、手順の更新など）
   - 削除された記述（廃止された機能の記述の削除など）
3. 各記述が何に関連するか（API、設定、構成、依存、機能など）を特定する

### フェーズ3: コード差分の分析

差分に含まれるコードファイルの変更内容を分析し、ドキュメントへの反映が必要な変更を特定する。

#### チェック観点

| カテゴリ | ドキュメント反映が必要な変更 |
|---------|--------------------------|
| **API / インターフェース** | エンドポイントの追加・変更・削除、関数シグネチャの変更、CLI引数の変更、レスポンス形式の変更 |
| **データモデル** | テーブル・カラムの追加・変更・削除、リレーションの変更、マイグレーションの追加 |
| **設定・環境変数** | 環境変数の追加・変更・削除、設定ファイルの形式変更、デフォルト値の変更 |
| **ディレクトリ構成** | ファイル・ディレクトリの追加・移動・削除・リネーム |
| **依存関係** | ライブラリの追加・削除・バージョン変更 |
| **機能** | 新機能の追加、既存機能の動作変更、機能の廃止・削除 |
| **セットアップ / ビルド** | インストール手順の変更、ビルドコマンドの変更、デプロイ設定の変更 |
| **認証・認可** | ロール・権限の変更、認証フローの変更 |
| **エラー処理** | エラーコード・ステータスコードの追加・変更 |

#### 手順

1. 各コードファイルの差分を取得する（`git diff <merge-base>...HEAD -- <ファイル>`）
2. 変更箇所の周辺コンテキスト（関数全体、クラス全体）も必要に応じて読み取る
3. 上記チェック観点に該当する変更を特定し、記録する

### フェーズ4: 突き合わせと乖離検出

ドキュメント差分とコード差分を突き合わせ、乖離を検出する。

#### 検出パターン

| パターン | 状態 | 重大度の目安 |
|---------|------|------------|
| コード変更あり・ドキュメント更新なし | ドキュメントの更新漏れ | コード変更の影響度に応じて 🔴〜🟡 |
| ドキュメント変更あり・コード変更なし | 先行するドキュメント更新（実装待ち）または不要な変更 | 🟡〜🟢（情報として記録） |
| 両方変更あり・内容が矛盾 | ドキュメントとコードの不一致 | 🔴〜🟠 |
| 両方変更あり・内容が整合 | 正常（乖離なし） | — |

#### 手順

1. コード差分で特定した「ドキュメント反映が必要な変更」に対して、ドキュメント差分に対応する更新があるか確認する
2. ドキュメント差分で特定した記述変更に対して、コード差分に対応する変更があるか確認する
3. 両方に変更がある場合、内容が整合しているか確認する
4. 乖離があれば、具体的な箇所（コード側のファイル:行とドキュメント側のファイル:行）を記録する

### フェーズ5: レポート生成

1. `AskUserQuestion` で出力先をユーザーに確認する：
   - **GitHub Issue に作成**（推奨）: タイトルは `review: ドキュメント乖離レポート(<ブランチ名> → <比較先>, <YYYY-MM-DD>)` の形式
   - **ローカル MD ファイルに保存**: プロジェクトルートに `doc-drift-git-report.md` を生成する
2. 選択された出力先にレポートを出力する
3. レポートの要約をユーザーに報告する

#### レポート形式

```markdown

> 生成日時: YYYY-MM-DD HH:MM
> 対象プロジェクト: <プロジェクト名>
> 比較: `<現在のブランチ>` → `<比較先ブランチ>`
> コミット数: N

## コミット一覧

- `<hash>` <メッセージ>
- ...

## サマリー

| 指標 | 値 |
|-----|-----|
| 差分内のドキュメントファイル数 | N |
| 差分内のコードファイル数 | N |
| 検出した乖離数 | N |
| うちドキュメント更新漏れ | N |
| うちコード変更なし（先行更新） | N |
| うち内容の矛盾 | N |
| 重大度 🔴 | N |
| 重大度 🟠 | N |
| 重大度 🟡 | N |
| 重大度 🟢 | N |

- **コード差分**: `<ファイルパス>:<行番号>`
  > コード変更の内容を簡潔に説明
- **ドキュメント差分**: `<ファイルパス>:<行番号>`（または「変更なし — 更新漏れ」）
  > ドキュメントの該当記述を引用（変更がある場合は変更内容）
- **乖離の内容**: 具体的な不一致を説明
- **推奨アクション**: ドキュメントを更新する / 実装を修正する / 要確認

### 🟠 重要（更新漏れ・古い情報）

### 🟢 軽微（表記ゆれ・些細な不正確さ）

...

...

## チェック対象ファイル

### ドキュメントファイル
- [x] `README.md` — 乖離 N 件
- [x] `docs/setup.md` — 乖離なし
- ...

### コードファイル（ドキュメント反映が必要な変更あり）
- [x] `src/api/routes.ts` — 乖離 N 件
- [x] `package.json` — 乖離なし
- ...
```

#### 重大度の基準

| 重大度 | 基準 |
|-------|------|
| 🔴 重大 | API・データモデル・認証等の重要な変更にドキュメントが追随していない、またはドキュメントとコードが明確に矛盾している |
| 🟠 重要 | 設定・依存関係・セットアップ手順等の変更にドキュメントが追随していない |
| 🟡 提案 | 軽微な機能変更のドキュメント反映漏れ、ドキュメントの補足・改善で利用者体験が向上するもの |
| 🟢 軽微 | 表記ゆれ、バージョン番号の古さ、些細な不正確さ |

## ルール

- **差分に集中する。** 差分に含まれないドキュメントやコードは対象外
- 推測で乖離を報告しない。実際のコードとドキュメントの差分を確認して裏付けを取ること
- 乖離の報告には必ずコード側とドキュメント側の両方の具体的な箇所を示すこと
- レポートは事実ベースで書く。修正の判断はユーザーに委ねる
- コード変更の影響を正確に判断するため、変更箇所だけでなく周辺コンテキスト（関数全体、呼び出し元など）も確認する
- 🔴（重大）または🟠（重要）の乖離は必ずレポートに含める
- 🟡（提案）や🟢（軽微）は、明確なメリットがある場合のみレポートに含める
- コード内のコメントや docstring はチェック対象外とする（外部向けドキュメントのみ）
- 各フェーズの進捗は TodoWrite ツールで管理する
