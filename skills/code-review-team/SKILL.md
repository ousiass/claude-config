# code-review-team

Agent Teams を活用し、専門分野ごとのレビュアーが並列でコードレビューを行うスキル。多角的なレビューにより網羅性と品質を向上させる。

> **注意**: このスキルは Agent Teams を使用するため、通常の `code-review` スキルより多くのトークンを消費する。小規模プロジェクトには `code-review` の使用を推奨する。

## 引数

`code-review` スキルと同じ:
- 引数なし: カレントディレクトリのプロジェクト全体をチェック
- パス指定: 特定のディレクトリやファイルに絞ってチェック

## 実行プロセス

### フェーズ1: プロジェクト構造の把握

`code-review` スキルのフェーズ1と同じ手順でプロジェクト構造を把握し、該当するチェック観点を特定する。

### フェーズ2: チーム編成と並列レビュー

1. エージェントチームを作成する
2. プロジェクトの構成に応じてレビュアーをスポーンする

#### 必須レビュアー

- **architecture-reviewer** × 1
  - 担当: ファイル行数、ディレクトリ構成、重複コード、依存関係、関数の複雑度、デッドコード、マジックナンバー/ストリング、テスタビリティ
- **quality-reviewer** × 1
  - 担当: Makefile、Lint & Format、Git Hooks (husky)、環境変数管理、エラーハンドリング、ログ設計、テストカバレッジ・品質、CI/CD 設定、`.gitignore`

#### 条件付きレビュアー（プロジェクトの構成に応じてスポーン）

- **frontend-reviewer**（フロントエンドが存在する場合）
  - 担当: `code-review` スキルのフロントエンドチェック項目すべて（Atomic Design、Composables 分離、命名規則、責務分担、状態管理、型定義、a11y、バンドルサイズ）
- **backend-reviewer**（バックエンドが存在する場合）
  - 担当: `code-review` スキルのバックエンドチェック項目すべて（レイヤー分離、パス単位分割、コードドキュメント、Swagger、命名規則、バリデーション、認証・認可、DB アクセス、レートリミット、ヘルスチェック、グレースフルシャットダウン）
- **security-reviewer**（大規模プロジェクトの場合）
  - 担当: セキュリティ脆弱性全般、認証・認可、入力検証、データ漏洩、OWASP Top 10
- **performance-reviewer**（大規模プロジェクトの場合）
  - 担当: N+1 クエリ、メモリリーク、不要ループ、パフォーマンスボトルネック

3. 各レビュアーのスポーンプロンプトに含める情報：
   - `code-review` スキルの該当チェック項目の詳細基準
   - 重大度の分類基準（🔴重大 / 🟠重要 / 🟡提案 / 🟢軽微）
   - レポート形式（ファイルパス:行番号、問題の説明、推奨アクション）
4. 共有タスクリストにレビュアーごとのタスクを作成する

### フェーズ3: レポート統合

1. 全レビュアーの結果を収集する
2. 重複する指摘を統合する（複数のレビュアーが同じ問題を検出した場合）
3. `code-review` スキルのレポート形式に従い、統合レポートを生成する
4. `AskUserQuestion` で出力先をユーザーに確認する：
   - **GitHub Issue に作成**（推奨）: タイトルは `review: コード品質レポート(<ブランチ名>, <YYYY-MM-DD>)` の形式
   - **ローカル MD ファイルに保存**: プロジェクトルートに `code-review-report.md` を生成する
5. レポートの要約をユーザーに報告する

### フェーズ4: チーム解散

1. すべてのチームメイトにシャットダウンを要求する
2. チームリソースをクリーンアップする

## チームメイトの役割

| 役割 | 人数 | 条件 | 責務 |
|------|------|------|------|
| architecture-reviewer | 1 | 必須 | アーキテクチャ、構造、依存関係のレビュー |
| quality-reviewer | 1 | 必須 | テスト、CI/CD、lint/format、エラー処理のレビュー |
| frontend-reviewer | 0〜1 | フロントエンドあり | フロントエンド固有のレビュー |
| backend-reviewer | 0〜1 | バックエンドあり | バックエンド固有のレビュー |
| security-reviewer | 0〜1 | 大規模 PJ | セキュリティ脆弱性のレビュー |
| performance-reviewer | 0〜1 | 大規模 PJ | パフォーマンス問題のレビュー |

## ルール

- すべてのレビュアーは読み取り専用。コードを変更しない
- 各レビュアーは担当ドメインのみをレビューする
- 指摘には必ずファイルパスと行番号を含める
- リードは結果を統合し、重複を除去すること
- 統合レポートは `code-review` スキルのレポート形式に従う
- 重大度の基準は `code-review` スキルと同一
- チームメイトがエラーで停止した場合、リードが確認し再スポーンまたは対処する
- 各フェーズの進捗は共有タスクリストで管理する
