# impl-team

Agent Teams を活用し、複数の開発者がスコープごとに並列で実装・レビューを行うスキル。Contract-First アプローチでインターフェースを事前定義し、安全な並列開発を実現する。

> **注意**: このスキルは Agent Teams を使用するため、通常の `impl` スキルより多くのトークンを消費する。並列化のメリットが少ない小規模タスクには `impl` の使用を推奨する。

## 引数

`impl` スキルと同じ:
- **Issue 番号** (例: `/impl-team #123`): GitHub Issue から要件を取得する。`gh issue view` で内容を読み取る
- **Issue URL** (例: `/impl-team https://github.com/owner/repo/issues/123`): 同上
- **テキスト** (例: `/impl-team ユーザー認証とAPIを追加`): テキストをそのまま要件として扱う
- **引数なし**: ユーザーに要件をヒアリングしてから開始する

## 実行プロセス

### フェーズ1: 要件分析とスコープ分割

`impl` スキルのフェーズ1と同じ手順で要件を取得し、ブランチを作成する。

スコープ分割時は以下に注意：
- **ファイル所有権の分離**: 各スコープが編集するファイルが重複しないように分割する
- 同じファイルを複数の開発者が編集する必要がある場合、それらは1つのスコープにまとめる
- 並列実行可能なスコープを最大化する

### フェーズ2: Contract-First 定義

開発者をスポーンする前に、共有インターフェースを定義してコミットする：
- 型定義 / インターフェース
- 関数シグネチャ
- API エンドポイントの形
- データモデルスキーマ

**契約定義をコミットしてから、次のフェーズに進む。**

### フェーズ3: チーム編成と並列実装

1. エージェントチームを作成する
2. チームメイトをスポーンする：
   - **developer** × N（並列実行可能なスコープ数。通常2〜5名）
     - Plan approval を有効にする（実装前にリードが計画を承認する）
     - スポーンプロンプトに含める情報：
       - 担当スコープの要件
       - フェーズ2で定義した契約（型定義、インターフェース等）
       - 所有ファイル一覧（この範囲のみ編集可能）
       - テスト要件
   - **reviewer** × 1〜2（Plan approval は不要）
     - スポーンプロンプトに含める情報：
       - レビュー基準（正確性、可読性、シンプルさ、セキュリティ、パフォーマンス、テスト十分性）
3. 共有タスクリストにタスクを作成する：
   - 各スコープの実装タスク（担当開発者にアサイン）
   - 各スコープのレビュータスク（実装タスクへの依存関係を設定、レビュアーにアサイン）
4. 開発者が並列で実装を進める
5. 各スコープの実装完了後、レビュアーがレビューする
6. レビュー指摘は担当開発者にフィードバックし、修正 → 再レビューを繰り返す

### フェーズ4: 統合と品質確認

1. すべてのタスクの完了を待つ
2. 全体のテストを実行する
3. 変更ファイルに format / lint を実行する
4. 統合上の問題があれば対処する（必要に応じて開発者を追加スポーン）
5. 残りの変更をコミットする

### フェーズ5: PR 作成

`impl` スキルのフェーズ3と同じ手順で PR を作成する。

### フェーズ6: チーム解散

1. すべてのチームメイトにシャットダウンを要求する
2. チームリソースをクリーンアップする

## チームメイトの役割

| 役割 | 人数 | 責務 |
|------|------|------|
| developer | 2〜5 | 担当スコープの実装とテスト。所有ファイルのみ編集する |
| reviewer | 1〜2 | 各スコープのコードレビュー。指摘は重大度付きで報告する |

## ルール

- **リードは各スコープの実装を行わない。** 統合・品質確認フェーズでの最小限の調整は許容する
- 各開発者のファイル所有権は重複してはならない
- 契約定義は開発者のスポーン前にコミットすること
- レビュー指摘はすべての重大度（🔴🟠🟡🟢）で修正する
- 各開発者は担当スコープ完了時にコミットすること
- チームメイトがエラーで停止した場合、リードが確認し再スポーンまたは対処する
- 各フェーズの進捗は共有タスクリストで管理する
