# doc-drift-team-max

複数のドキュメントチェッカーがグループごとに並列でチェックを行い、大量のドキュメントを効率的に検証する。

> **注意**: Agent Teams を使用するため `doc-drift-max` より多くのトークンを消費する。ドキュメントが少数の場合は `doc-drift-max` を推奨。

## 前提条件

- Claude Code 環境
- `gh` CLI（GitHub Issue 出力時）

## 引数

`doc-drift-max` と同じ:
- 引数なし: プロジェクト全体をチェック
- パス指定: 特定のドキュメントに絞ってチェック

## フェーズ1: ドキュメント探索とグループ分け

1. `doc-drift-max` のフェーズ1と同じ手順でドキュメントを探索
2. ドキュメントをグループに分ける（ディレクトリ・テーマ単位で2〜4グループ）

## フェーズ2: チーム編成と並列チェック

1. エージェントチームを作成
2. **doc-checker** × N（グループ数、2〜4名）をスポーン
   - **読み取り専用**（コードもドキュメントも変更不可）
   - プロンプトに含める: 担当グループ一覧、チェック観点（`doc-drift-max` の `references/check-criteria.md`）、重大度基準、レポート形式
3. 共有タスクリストにグループごとのタスクを作成

## フェーズ3: レポート統合

1. 全チェッカーの結果を収集
2. `doc-drift-max` のレポート形式（`templates/report.md`）に従い統合レポートを生成
3. `AskUserQuestion` で出力先をユーザーに確認する：
   - **GitHub Issue に作成**（推奨）: `review: ドキュメント乖離レポート(<ブランチ名>, <YYYY-MM-DD>)`
   - **ローカル MD ファイルに保存**: プロジェクトルートに `doc-drift-report.md` を生成
4. 要約をユーザーに報告

## フェーズ4: チーム解散

全チームメイトにシャットダウン要求 → チームリソースをクリーンアップ

## チームメイトの役割

| 役割 | 人数 | 責務 |
|------|------|------|
| doc-checker | 2〜4 | 担当グループの乖離チェック。読み取り専用 |

## ルール

- チェッカーは読み取り専用。コードもドキュメントも変更しない
- 各チェッカーは担当グループのみチェック
- 仕様書を正（Single Source of Truth）として扱う
- 乖離にはドキュメント側と実装側の両方の箇所を示す
- 重大度基準は `doc-drift-max` と同一
- チームメイトがエラーで停止した場合、リードが再スポーンまたは対処する
- 共有タスクリストで進捗を管理する
