# ブランチ命名規則

## Issue にブランチ名が記載されている場合

1. Issue 本文にブランチ名が記載されているか確認する
2. ブランチがリモートまたはローカルに存在する場合:
   - `git fetch origin && git checkout <ブランチ名>`
   - ベースブランチはチェックアウト前のブランチ
   - **新しいブランチは作成しない**
3. ブランチ名が記載されていない、またはブランチが存在しない場合:
   - 以下のルールで新しいブランチを作成する

## 新しいブランチを作成する場合

### プレフィックス

| プレフィックス | 用途 |
|---|---|
| `feat/` | 新機能の追加 |
| `fix/` | バグ修正 |
| `refactor/` | リファクタリング |
| `docs/` | ドキュメントのみの変更 |
| `test/` | テストの追加・修正のみ |

判定に迷う場合は `feat/` をデフォルトとする。

### ブランチ名のフォーマット

**Issue 指定時:**
- Issue のラベル・タイトルから type を判定し `<type>/#<Issue番号>` とする
- ラベル `bug` → `fix/`、`enhancement`/`feature` → `feat/`
- 例: `feat/#39`, `fix/#42`

**テキスト / 引数なし:**
- 要件の内容から type を判定し `<type>/<要件を要約した短い名前>` とする
- 例: `feat/add-auth`, `fix/login-error`
